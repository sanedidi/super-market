# Публичные страницы super-market.uz

Статические страницы без сборки: HTML + CSS + немного JS. В образ nginx
копируются в `/usr/share/nginx/html/site` (см. `web/Dockerfile`; этот README в
образ не попадает). Макет — Figma «Landing page» (файл `RV7wi3GFa6K8PgshOrW5mP`,
страница `308:848`).

| Адрес | Файл | Что это |
|---|---|---|
| https://super-market.uz/ | `index.html` | Лендинг (RU) |
| https://super-market.uz/uz | `uz.html` | Лендинг (UZ, латиница) |
| https://super-market.uz/privacy | `privacy.html` | Политика конфиденциальности (RU) |
| https://super-market.uz/privacy/uz | `privacy-uz.html` | Maxfiylik siyosati (UZ, латиница) |
| https://super-market.uz/courier-terms | `courier-terms.html` | Условия для курьеров «по пути» |
| https://super-market.uz/delete-account | `delete-account.html` + `delete-account.js` | Удаление аккаунта без приложения (ссылка для Google Play) |
| https://super-market.uz/robots.txt, /sitemap.xml | `robots.txt`, `sitemap.xml` | Для поисковиков |

Общие файлы:

- `landing.css` — стили лендинга и **общие для всех страниц** шапка, подвал,
  кнопки `.button`, шрифты и цвета. Подключается первым.
- `site.css` — только документы: раскладка «оглавление + карточка», текст,
  форма удаления аккаунта.
- `landing.js` — на всех страницах: внешние ссылки (`LINKS`), мобильное меню,
  тарифы из API, подсветка пункта оглавления в документах.
- `img/` — картинки лендинга (`hero-phones.webp`, `pos.webp`,
  `buyers-phones.webp`) и `og.jpg` 1200×630 для превью ссылки в мессенджерах.

Шапка и подвал скопированы в каждый HTML-файл (сборки нет). Меняете пункт меню
или подвала — поправьте во всех шести файлах (`grep -n "site-footer" *.html`).
Русский и узбекский лендинги — два отдельных файла с одинаковой разметкой:
правка текста или вёрстки в `index.html` — такая же правка в `uz.html`.

Тексты документов сконвертированы из черновиков `privacy.md`, `privacy_uz.md`,
`courier-terms.md`, `delete-account.md`. Дальше правьте **HTML напрямую**.
Если меняете русскую политику — поправьте и узбекскую.

## Маршруты

- `deploy/nginx.conf` (nginx в Docker): лендинг лежит на внутренних адресах
  `/landing` и `/landing/uz` — на `store.super-market.uz` адрес `/` занят
  панелью магазина. Документы — точные `location` (`/privacy`, …), файлы —
  `location ^~ /site/`.
- `deploy/host-nginx.conf` (nginx на сервере), блок `super-market.uz`:
  `/` → `/landing`, `/uz` → `/landing/uz`, `/robots.txt` и `/sitemap.xml` →
  `/site/…`, документы и `/site/` — как есть, `/api/` — как раньше; всё
  остальное — 302 на `store.super-market.uz`. `www.super-market.uz` теперь
  отвечает 301 на `super-market.uz` (кроме `/api/`).
- Документы и `/site/` по-прежнему открываются и на `store.super-market.uz`
  (там проксируется всё), лендинг там — только на `/landing`.
- Кэш: HTML, CSS и JS — `no-cache` (браузер переспрашивает и получает 304, пока
  файл не изменился), картинки в `/site/img/` — неделю. Поменяли картинку —
  дайте ей новое имя (или подождите неделю).

## Ссылки (`LINKS` в начале `landing.js`)

Все внешние ссылки сайта собраны в одном объекте; в HTML у таких ссылок есть
атрибут `data-link="<ключ>"`, скрипт подставляет адрес при загрузке. Пустая
строка — ссылки пока нет: кнопка видна, но ведёт на `#` и помечена
`aria-disabled` (клик ничего не делает).

| Ключ | Где | Сейчас |
|---|---|---|
| `login` | «Войти», «Войти в панель» | `https://store.super-market.uz/` |
| `register` | «Подключить магазин», «Подключить сеть» | `https://store.super-market.uz/` — отдельной страницы регистрации в панели нет: вход по номеру, затем мастер настройки магазина |
| `telegram` | «Написать в Telegram», подвал «Telegram» | пусто — вписать `https://t.me/<бот>` (то же, что `SUPPORT_URL`) |
| `support` | подвал «Поддержка» | пусто — `mailto:…` или страница поддержки |
| `offer` | подвал «Публичная оферта» | пусто — то же, что `OFFER_URL`, когда оферта появится |
| `clientAppStore`, `clientGooglePlay` | значки в блоке «Покупателям», подвал | пусто (пакет Android: `uz.supermarket.sm_client`) |
| `courierAppStore`, `courierGooglePlay` | значки в блоке «Курьерам» | пусто |

Подвал «SM Курьер» — одна ссылка: на iPhone/iPad ведёт в App Store, на
остальных — в Google Play (`courierApp` в скрипте). Без JS работают только
ссылки, у которых адрес уже вписан в HTML (`login`, `register`).

## Тарифы

Блок «Тарифы», цифра «от 15 $» в первом экране и ответ «Можно подключить сеть
магазинов?» берутся из `GET /api/v1/public/tariffs` — их меняет супер-админ в
админке («Биллинг»), сайт править не нужно:

- карточка на каждый действующий тариф; заголовок из диапазона
  («1–2 магазина», «3 и более магазинов», «1 магазин»; по-узбекски
  «1–2 ta do‘kon», «3 va undan ko‘p do‘kon»); цена «20 $» (`.00` отбрасывается,
  иначе «12,50 $»);
- самый дешёвый тариф — красная рамка, значок «Выгоднее» и красная кнопка
  (если тариф один — без рамки и значка); кнопка «Подключить сеть», если тариф
  начинается от 2 магазинов, иначе «Подключить магазин»;
- список «что входит» одинаковый для всех карточек — он берётся из первой
  статичной карточки в HTML (`data-tariff="features"`); меняется в HTML;
- если API не ответил или ответил ошибкой — остаются статичные карточки из HTML
  (1–2 магазина 20 $, 3 и более 15 $). **Изменились цены — поправьте и эти
  карточки** (в `index.html` и `uz.html`), а также `description` в `<head>`;
- если действующих тарифов нет — вместо карточек «стоимость подскажем в
  поддержке», цифра в первом экране скрывается.

## Проверка локально

Нужны nginx и Python. Скопируйте `deploy/nginx.conf`, замените `root` на путь
к папке, где лежит `site/` (например, симлинк на `web/site`), `resolver`
уберите, `$api_upstream` направьте на backend или на заглушку, которая отдаёт
`{"items":[…]}` на `/api/v1/public/tariffs`. Лендинг откроется на
`http://127.0.0.1:<порт>/landing` и `/landing/uz`.

## Удаление аккаунта

Форма на `/delete-account` работает в 3 шага и ходит в API того же домена:

1. `POST /api/v1/public/account-deletion/request` `{phone}` — код в Telegram-бот (если номер к нему привязан) или по SMS.
2. `POST /api/v1/public/account-deletion/confirm` `{phone, code}` — аккаунты покупателя и курьера «по пути» удаляются сразу; для сотрудников магазина и штатных курьеров создаётся запрос супер-админу.
3. Экран «Готово» со списком того, что сделано.

Если есть незавершённый заказ или невыплаченный баланс курьера, ничего не
удаляется, а код сгорает — страница просит сначала завершить заказ / получить
выплату и запросить новый код.

## Что проверить до публикации (из заметок к черновикам)

- **Ст. 27-1 ЗРУ-547:** сервер с PostgreSQL и MinIO должен физически находиться в Узбекистане — иначе раздел 9 политики недостоверен.
- Нужна ли регистрация базы в Государственном реестре баз персональных данных (номер — в раздел 1 политики).
- Трансграничная передача (Firebase, Яндекс, Telegram, OpenStreetMap, OpenAI/Anthropic) — формулировки раздела 8 проверить юристу.
- Сроки хранения бухгалтерских данных («не менее 5 лет»), «до 3 лет» для отпечатка документа, «10 рабочих дней» на ответ, «до 30 дней» на запросы — утвердить.
- Условия курьеров: налоги (самозанятость или удержание НДФЛ, п. 8.5), характер договора (ГПХ), ответственность (раздел 10), товары 18+ в доставке «по пути», допускаются ли иностранные документы (п. 1.3).
- Кнопка «Удалить аккаунт» в приложении курьера (Apple 5.1.1(v)) — тексты ссылаются на «Профиль → Удалить аккаунт».

## Настройки окружения

В секрете GitHub `PROD_ENV` (переменные для `deploy/docker-compose.prod.yml`)
укажите ссылки, которые backend отдаёт приложениям:

```
PRIVACY_URL=https://super-market.uz/privacy
OFFER_URL=<адрес оферты для покупателей>
```

Оферта для покупателей (`OFFER_URL`) — отдельный документ, на этих страницах
её пока нет. Если её тоже сделать здесь, добавьте файл в `web/site/` и
`location` в оба nginx-конфига по образцу `/courier-terms`.

Эти же адреса указываются в App Store Connect и Google Play Console:
политика — `https://super-market.uz/privacy`, удаление аккаунта —
`https://super-market.uz/delete-account`.
